# الدليل الفني الشامل لنظام صحة السيو والأرشفة (SEO Health & GSC Architecture)
### منصة كود التطور البرمجية — https://code-elta6ur.com/

---

## 1. مقدمة ونظرة عامة
تم تصميم وبناء هذا النظام البرمجي المتكامل داخل القالب المخصص (`code-elta6ur-theme`) لعلاج وتصحيح كافة مشاكل الأرشفة والفهرسة المبلغ عنها في **Google Search Console (GSC)**، وتوفير ميزانية الزحف (Crawl Budget)، ورفع إشارات الجودة، ومنع تكرار الوسوم مع إضافات السيو (Yoast / Rank Math / SEOPress / AIOSEO).

---

## 2. الهيكلية المعمارية للملفات (`inc/seo-health/`)
يتم تحميل النظام تلقائياً عبر نقطة دخول موحدة في `functions.php`:
```
code-elta6ur-theme/
├── inc/
│   ├── seo-health/
│   │   ├── seo-health-init.php      # التهيئة العامة، تعريف الثوابت، فحص الإضافات، وإنشاء الجداول
│   │   ├── indexing-policy.php      # سياسة الفهرسة المركزية (noindex,follow) وحماية المحتوى الأساسي
│   │   ├── redirects.php            # إدارة تحويلات 301 و 410 وحماية سلاسل وحلقات التوجيه
│   │   ├── 404-log.php              # تسجيل 404 المجمع والاقتراح الذكي للروابط البديلة (Smart Suggestions)
│   │   ├── slug-repair.php          # كشف وإصلاح الروابط المعطوبة المسقط منها علامة الـ % وتراجعها
│   │   ├── canonical-urls.php       # توحيد الروابط القانونية، إزالة باراميترات التتبع، وحجب replytocom
│   │   ├── robots.php               # توليد وتخصيص robots.txt الديناميكي مع توجيهات Sitemap
│   │   ├── server-health.php        # فحص استقرار الخادم، محاكاة Googlebot، وقراءة debug.log
│   │   ├── thin-pages.php           # منع Soft 404 على الأرشيفات الفارغة وفحص المحتوى الرقيق
│   │   ├── quality-signals.php      # كاش المقالات ذات الصلة، بيانات Schema المنظمة للأدوات، وخريطة الموقع
│   │   ├── admin-dashboard.php      # لوحة التحكم المركزية في الأدمن (تبويبات، إحصائيات، وتصدير CSV)
│   │   └── cli-commands.php         # حزمة أوامر WP-CLI الشاملة للأتمتة والفحص السريع
```

## 3. جداول قواعد البيانات المخصصة (Database Schema)
أنشأ النظام جدولين مخصصين عاليي الأداء باستخدام معايير `dbDelta` مع فهارس محسنة:

### أ) جدول التحويلات `{$wpdb->prefix}seo_redirects`:
- `id` (bigint unsigned auto_increment primary key)
- `source_path` (varchar(255) unique key) — المسار المصدر بعد تطبيعه وفك ترميزه
- `target_url` (text) — الرابط الهدف بعد حل سلاسل التوجيه
- `status_code` (smallint unsigned default 301) — 301 دائم، 302 مؤقت، 410 محذوف نهائياً
- `hits` (bigint unsigned default 0) — عداد الزيارات التراكمي
- `created_at` (datetime) — تاريخ الإنشاء
- `source_type` (varchar(50)) — manual / auto / slug-fix

### ب) جدول سجل أخطاء 404 `{$wpdb->prefix}seo_404_log`:
- `id` (bigint unsigned auto_increment primary key)
- `normalized_path` (varchar(255) unique key) — المسار المفقود المطبع
- `hits` (bigint unsigned default 1) — تجميع الزيارات (UPSERT) بدلاً من تكرار السجلات
- `last_seen` (datetime) — آخر وقت طلب فيه الرابط
- `referrer_host` (varchar(191)) — اسم نطاق الإحالة فقط (دون تخزين أي بيانات شخصية أو IPs)
- `user_agent_type` (varchar(50)) — تصنيف المتصفح: googlebot / bingbot / other_crawler / browser
*(يتم تنظيف السجلات الأقدم من 90 يوماً تلقائياً عبر كرون يومي مجدول)*

## 4. سياسة الفهرسة المركزية (`indexing-policy.php`)

### صفحات خاضعة لـ `noindex,follow`:
1. صفحات الحساب والمصادقة (`/login/`, `/registration/`, `/lost-password/`, `/my-account/`).
2. نتائج البحث الداخلي (`/?s=`, `/search/`).
3. الروابط الملوثة بباراميترات الفلترة والترتيب (`filter`, `sort`, `orderby`).
4. صفحات المرفقات الفردية (مع توجيه 301 إلى المقال الأب).
5. أرشيف التواريخ (السنوات والشهور والأيام).
6. أرشيف المؤلف (المنصة ذات مؤلف تقني رئيسي موحد).
7. أرشيف الوسوم التي تحوي أقل من 5 مقالات (Thin Tags).
8. قوالب Elementor الداخلية (`elementor_library`).

### صفحات محمية تماماً وتُفهرس دائماً بـ `index,follow`:
- الصفحة الرئيسية (`/`).
- مقالات المدونة والدروس التعليمية.
- صفحات الكورسات ومناهجها (`/الكورسات-التعليمية/`, `كورس-html`, `كورس-css`, إلخ).
- السلاسل التعليمية (`cat_series`).
- مركز الأدوات البرمجية والأدوات الفردية (`/tools/`, `/tools/{slug}/`).
- محرر الأكواد أونلاين ولغاته (`/editor/`, `/editor/{lang}/`).
- الصفحات الأساسية (من نحن، اتصل بنا، سياسة الخصوصية، شروط الاستخدام).
- صفحات الترقيم (`/page/2/`) تبقى `index,follow` مع كانونيكال ذاتي لكل صفحة.

## 5. إدارة الكانونيكال ومنع تكرار الروابط (`canonical-urls.php`)
- **رابط كانونيكال ذاتي (Self-Canonical):** لكل صفحة قابلة للفهرسة.
- **إزالة باراميترات التتبع تلقائياً:** يتم تجريد وسوم `utm_*`, `fbclid`, `gclid`, `replytocom`, `ref`, `share`, `amp`, و `?s=` الفارغة من رابط الكانونيكال.
- **إلغاء روابط `replytocom`:** تم فلترة روابط الرد على التعليقات لحذف هذا الباراميتر ومنع توليد آلاف الروابط المكررة في ميزانية الزحف.
- **منع التكرار:** في حال وجود إضافة سيو نشطة (Yoast / Rank Math / SEOPress) يتم حقن الرابط النظيف عبر فلاتر الإضافة دون طباعة وسم مكرر في `<head>`.

## 6. أوامر WP-CLI المتاحة للمدير التقني

```bash
# 1. عرض تقرير شامل بالصفحات المحجوبة بـ noindex مصنفة بالنوع
wp seo-health noindex-report

# 2. فحص الروابط الداخلية المكسورة داخل محتوى المقالات
wp seo-health broken-links

# 3. فحص الروابط المعطوبة (Hex Slugs) بوضع المعاينة (Dry-Run افتراضي)
wp seo-health slugs --dry-run

# 4. تطبيق تصحيح الروابط المعطوبة، إنشاء 301، وتحديث المحتوى
wp seo-health slugs --apply

# 5. التراجع الآمن عن آخر عملية إصلاح للروابط
wp seo-health slugs --rollback

# 6. فحص المحتوى الرقيق والصفحات اليتيمة (Orphan Posts)
wp seo-health thin --min-words=600

# 7. فحص ومراجعة روابط خريطة الموقع (Sitemap Audit)
wp seo-health sitemap-audit --sample=30
```

## 7. لوحة التحكم في ووردبريس (`WP Admin > صحة السيو`)
تحتوي اللوحة المركزية على:
1. **نظرة عامة (Overview):** إحصائيات حية بالتحويلات، أخطاء 404، طلبات Googlebot، وحالة إضافة السيو.
2. **التحويلات وسجل 404:** جدول بأكثر صفحات 404 زيارة مع زر "إنشاء 301 سريع"، وإضافة/تعديل التحويلات، وتصدير CSV.
3. **سياسة الفهرسة (Indexing Policy):** مفاتيح تحكم بسيطة لتفعيل/تعطيل قواعد noindex وتحديد الحد الأدنى للوسوم.
4. **فحص المحتوى الرقيق:** جدول تفاعلي بالصفحات التي تحتاج إلى إثراء مع بيان عدد الكلمات وتوفر H2 والصور وحالة اليتم (Orphan).
5. **فحص الخادم و Googlebot:** أداة محاكاة زحف Googlebot للتأكد من عدم وجود حجب 403 أو 500، مع عارض لآخر 50 سطراً من `debug.log`.
6. **الإعدادات:** التحكم بنسبة الثقة للتحويل التلقائي لصفحات 404 والحد الأدنى للكلمات.

## 8. خطوات العمل في Google Search Console بعد تطبيق التحديث
1. **لا تضغط على زر "التحقق من الإصلاح (Validate Fix)" فوراً.**
2. توجه إلى قسم **خرائط الموقع (Sitemaps)** وأعد إرسال رابط خريطة الموقع:
   - في حال استخدام ووردبريس الافتراضي: `/wp-sitemap.xml`
   - في حال استخدام Rank Math أو Yoast: `/sitemap_index.xml`
3. استخدم أداة **فحص الروابط (URL Inspection)** وافحص عينة من:
   - رابط صفحة رئيسية أو مقال: تأكد من ظهور `URL is on Google` ورابط الكانونيكال الذاتي.
   - رابط صفحة حساب مثل `/login/`: تأكد من ظهور `Excluded by ‘noindex’ tag`.
   - رابط مكسور تم تحويله: تأكد من استجابة `301 Moved Permanently`.
4. بعد التأكد من صحة النتائج لعينة من 5 إلى 10 روابط، اضغط على **Validate Fix** في Search Console لكل تصنيف خطأ.
